TCP Client: connect this node outward

TCP Client
This node → Remote server

Before you connect to a remote Reticulum server, you need:

  • Remote server hostname or IP address
  • Remote server TCP Listen Port
  • IFAC network name and passphrase, if that server uses IFAC
  • Custom IFAC size only if the remote operator specifies one
  • Confirmation that the remote server accepts TCP connections

These values are provided by the remote server operator. IFAC settings belong only to this interface; they never reuse IFAC from another interface on this node.

What are you trying to accomplish?

This node will use the remote connection itself. Transport Mode can remain Off.

This node becomes a path for other peers. Transport Mode must be enabled, and another usable interface—such as TCP Server, AutoInterface, or RNode—is needed for those peers to reach this node.

The hostname or IP address of the remote TCP Server this client connects to.

The remote server’s Listen Port. It must match that server’s Listen Port.

Example: remote server listen_ip = 100.64.10.20, listen_port = 4242; this node target_host = 100.64.10.20, target_port = 4242.

TCP Server: let others connect inward

TCP Server
Remote node → This node

Before another Reticulum node can connect to this server:

  • Choose a local Listen IP and Listen Port
  • Ensure the client can reach that address
  • Configure matching IFAC on both sides when IFAC is enabled
  • For Tailscale, both machines must be in the same tailnet and policies must allow the connection
  • For public Internet use, external reachability must exist separately

Creating a TCP Server does not configure your router, firewall, or Tailscale. For private trusted links, Tailscale is usually easier and safer than opening a router port.

The local address assigned to this server where this TCP Server waits for connections. In the managed Linux installation, rnsd uses host networking: 0.0.0.0 means all host IPv4 interfaces; 192.168.1.85 means that host LAN address only; and a host 100.x.x.x address means Tailscale only. Do not normally enter your public Internet IP here.

The local port where this TCP Server accepts connections. One IP can host several servers if each uses a different port: Public Users :4242, Trusted Backbone :4243, Testing :4244.

AutoInterface: nearby LAN discovery

AutoInterface discovers nearby Reticulum nodes on the same local network automatically. No remote server address is needed.

Prerequisites: compatible local networking and IPv6/link-local availability where required by Reticulum.

IFAC Access Protection

IFAC is shared access protection for this one interface, similar to a shared Wi-Fi password—not a per-user login.

Leave size at the interface default unless the remote operator requires a custom size. For a TCP Client, enter values supplied by the remote server operator. For a TCP Server, give connecting users the values configured here.

Using Tailscale

For a private link, the server can use its Tailscale IP and port, while the client targets that Tailscale IP or MagicDNS name and the same port. Tailscale must already be installed on both machines, both must be in the same tailnet, and ACLs/policies must permit the connection.

Server: listen_ip = server’s Tailscale IP; listen_port = 4243
Client: target_host = server’s Tailscale IP or MagicDNS name; target_port = 4243
